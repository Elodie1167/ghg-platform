## 1. 新增一個工廠

1. 首頁點右上角「**工廠設定**」
2. 停在「工廠」分頁，點「**+ 新增工廠**」
3. 填寫：
   - **廠代碼**：大寫英數與底線，慣例是 `產區_簡稱`，例如 `THA_MK`。
     ⚠️ **建立後不能修改**，請先想好
   - **中文名稱**、**英文名稱**
   - **產區**：從下拉選單挑。如果要的產區不在清單裡，先做第 4 節
4. 按「建立」

新廠會自動排在該產區的最後面，並且**立刻**出現在首頁、填報頁、集團碳排彙整表、
減碳績效追蹤與 Excel 匯出。不需要通知任何人改程式。

**接著要做的兩件事：**
- 到「**係數設定**」確認這個廠適用的排放係數（沒有係數，填報後會算出 0）
- 到該廠填報頁設定它要填哪些排放源（見第 8 節）
- 如果這個廠會出現在 CSR 明細表裡，到「CSR 廠名對照」分頁新增對照（見第 9 節）

## 2. 移除／關閉一個工廠

**請一律用「停用」，不要用「刪除」。**

1. 「工廠設定」→ 找到該廠 → 按「**停用**」
2. 確認彈出的說明

停用之後：
- ✅ 不再出現在首頁填報入口
- ✅ 不再被異常提醒檢查（不會一直報缺月）
- ✅ **歷史年度的彙整表與報表照常列出這個廠** —— 已經盤查過的年度不會因為關廠
  就少一個廠，這是盤查揭露的要求

要恢復就按「啟用」，資料完全不受影響。

### 什麼時候可以用「刪除」

只有**建錯了、完全沒有任何填報記錄與 iREC 憑證**的廠，才會出現「刪除」按鈕。
有資料的廠即使按了也會被系統擋下，並提示改用停用。

### 兩個廠要合併怎麼辦

例如 `CAB_MK1`、`CAB_MK2`、`CAB_MK5` 要併成 `CAB_MK`。
**這件事不能在網頁上做**，需要請 Claude 寫一支 migration 處理（要把歷史記錄
搬到新廠、去除重複、再刪舊廠）。作法見 [`請Claude做的事.md`](請Claude做的事.md)。

## 3. 調整工廠或產區的顯示順序

**工廠**：「工廠設定」→「工廠」分頁 → 用每列左邊的 ↑ ↓ 調整。
只能在同一個產區內調整順序。

**產區**：「工廠設定」→「產區」分頁 → 直接改「順序」欄的數字（數字小的排前面），
點到別的地方就會存檔。

產區順序會同時影響**首頁、集團碳排彙整表、減碳績效追蹤**三個地方，三者共用同一份。

## 4. 新增一個產區（國家）

1. 「工廠設定」→「**產區**」分頁
2. 在下方「新增產區」填代碼（3 碼大寫，如 `THA`）、中文名、英文名
3. 按「新增」

新產區預設排在最後，可再依第 3 節調整順序。

## 5. 新增一個排放源

排放源代碼有既定編碼規則，格式是 `範疇-類別-序`，例如 `1-1A-1`（範疇一、固定燃燒 A 類、第 1 項）。
新增前請先確認要歸在哪個範疇與類別。

目前排放源的新增走 API（`/api/admin/emission-sources`）。若不熟悉，
請直接請 Claude 幫忙，講清楚：代碼、中文名、範疇（1/2/3）、預設單位、是否為生質燃料。

**新增後一定要接著建排放係數**，否則填報了也算出 0。

---

## 6. 停用一個排放源

停用是「這個排放源全集團都不再使用」。停用之後：
- 填報頁不再出現該欄位
- **歷史記錄與既有數字完全不變**，仍可重算
- 重新啟用時，各廠原本的勾選設定原封不動（系統不會偷改）

有填報記錄或排放係數的排放源不能刪除，只能停用。

## 7. 每年更新排放係數

1. 首頁 → 「**係數設定**」
2. 用「**整年複製**」把上一年度的係數整批複製到新年度
3. 逐項更新數值，來源請填在「係數來源」欄（稽核會查）

各產區電力係數來源：

| 產區 | 來源 |
|------|------|
| TWN | 台灣電力公司（每年更新） |
| CHN | 中國官方市場剩餘電力排放係數 |
| NVN / SVN | 越南環境部公告 |
| IND | 印尼政府公告 |
| CAB / SLV / BGD | UNFCCC IFI Dataset |

### ⚠️ 改了係數，舊記錄不會自動更新

系統只會替「還沒算過」的記錄套用新係數。如果你改的是**已經填報過的年度**的係數，
想讓舊資料跟著變，**必須請 Claude 幫忙做重算**（要先把舊的計算結果清掉再重算）。

不做這一步的話，畫面會顯示舊數字或 0，而且**不會出現任何錯誤訊息**，很容易漏掉。

## 8. 設定某個廠要填哪些排放源

進該廠的填報頁（`/fill/廠代碼`），有排放源勾選設定。
只勾這個廠實際會用到的，填報畫面才不會落落長。

注意：一個排放源要能填，必須「這個廠有勾選」**而且**「該排放源沒有被全集團停用」。

## 9. 匯入 CSR 明細表

1. 進「減碳績效追蹤」（`/reduction`）
2. 設定引導的第一步可以直接上傳 CSR_Detail 檔案
3. 選年度後上傳

### 匯入後出現「查無設定」警告怎麼辦

警告會列出 CSR 檔裡有、但平台不知道要對到哪個廠的名稱，格式是 `產區｜廠名`。

1. 「工廠設定」→「**CSR 廠名對照**」分頁
2. 下方「新增對照」，把警告裡的產區與廠名照抄進去
3. 如果**應該匯入** → 選對應的平台廠
4. 如果**本來就不該匯入**（已關廠、樣品中心等）→ 勾「**刻意略過**」，之後就不會再提醒
5. 重新匯入一次

同一個平台廠可以對應多個 CSR 廠名（合併廠會自動加總），例如
`CAB｜MK1`、`CAB｜MK2`、`CAB｜MK5` 都對到 `CAB_MK`。

## 12. 常見狀況與處理

| 狀況 | 原因與處理 |
|------|-----------|
| 新增的廠沒出現在彙整表 | 重新整理頁面。若仍沒有，確認該廠是「啟用中」 |
| 填報後排放量是 0 | 該排放源在這個廠／年度沒有對應的排放係數。到「係數設定」檢查 |
| 改了係數但數字沒變 | 正常，見第 7 節。需要請 Claude 做重算 |
| 停用的廠還出現在彙整表 | 正常且刻意如此。該年度有填報資料的廠一定會列出 |
| CSR 匯入少了某個廠 | 看匯入警告，到「CSR 廠名對照」補設定，見第 9 節 |
| 減碳頁顯示「查無標打產能」 | CSR 產能沒匯入或該年度沒資料，重新匯入 CSR 明細表 |
| 網站打不開 | 請 IT 確認 192.168.6.102 上的 pm2 程序 `ghg-platform` 是否還在跑 |
| 忘記密碼／要換密碼 | 見第 14 節 |
| 貼上指令後出現「`&&` 語彙基元不是有效的分隔符號」或「已停用指令碼執行」 | 見第 13 節 |

**遇到手冊沒寫的狀況，直接開 Claude Code 問。** 平台的 `CLAUDE.md` 已經寫好規則，
Claude 讀得到，可以直接描述問題請它處理。

## 13. 在 PowerShell 貼指令時的兩個坑

平台跑在 Windows 上，你打開的黑色／藍色視窗是 **PowerShell 5.1**。
文件與網路上的指令大多是 Mac/Linux（bash）寫法，直接貼會失敗。**這不是你打錯，
也不需要改系統設定**，只要照下面換個寫法。

### 坑一：`&&` 不能用

看到這個錯誤：

```
'&&' 語彙基元不是有效的陳述式分隔符號
```

`&&` 的意思是「前一個成功才做下一個」，PowerShell 5.1 沒有這個寫法。改成：

| 原本（bash） | PowerShell 要這樣寫 |
|---|---|
| `A && B` | `A; if ($?) { B }` |
| `A; B`（不管成功都做） | `A; B`（一樣） |

### 坑二：`npm` 和 `pm2` 被擋

看到這個錯誤：

```
因為這個系統上已停用指令碼執行，所以無法載入 ...\npm.ps1 檔案
```

原因是 PowerShell 會去找 `npm.ps1`，而這台機器的安全設定不允許執行 `.ps1`。
**解法是在指令後面加 `.cmd`**：

| 原本 | 改成 |
|---|---|
| `npm run build` | `npm.cmd run build` |
| `npx ...` | `npx.cmd ...` |
| `pm2 restart ghg-platform` | `pm2.cmd restart ghg-platform` |

`node`、`git` 不受影響，可以直接用。

### 部署（改完程式後讓網站更新）完整寫法

```powershell
cd "C:\Users\elodiecheng\Desktop\Claude\溫盤\ghg-platform\apps\web"
npm.cmd run build; if ($?) { pm2.cmd restart ghg-platform; git push }
```

或更簡單，用批次檔（`.bat` 不受限制，已包好前兩步，之後再自己 `git push`）：

```powershell
cd "C:\Users\elodiecheng\Desktop\Claude\溫盤\ghg-platform"; .\deploy.bat
```

> ⚠️ `pm2 restart` 會讓網站中斷幾秒，**正在填報的人可能會中斷**。
> 請避開大家填報的時間，或先在群組說一聲。

### 另一個相關問題：`psql` / `pg_dump` 完全不能用

這兩個是被作業系統直接擋掉（`Access is denied`），**加 `.cmd` 也沒用**。
所以資料庫備份目前做不了（已列為待辦，需請 IT 排除）。
要查資料庫請開 Claude Code 說明需求，它會改用其他方式查。

## 14. 帳號與密碼

平台目前是 **email + 密碼** 登入，帳號資料存在資料庫裡。
（未來會改成用公司帳號直接登入，屆時不需要再記這組密碼。）

### 誰有帳號

四位：Elodie Cheng、Johnson Lin、Kelly Lin、Meng-Ying Hong，皆為管理者。

其中**只有 Elodie 與 Johnson 具備「查證封存」權限**。封存是不可逆的操作，
且封存後的數字就是對外揭露與報告書的來源，所以刻意只給兩個人，
兩個人是為了避免其中一位休假或離職時沒人能封存。

### 換密碼

```powershell
cd "C:\Users\elodiecheng\Desktop\Claude\溫盤\ghg-platform"
node scripts/create-user.mjs --reset 要改的email@makalot.com.tw
```

輸入新密碼時**畫面不會顯示任何字元**，這是正常的，打完按 Enter 即可，
會再要求輸入第二次確認。

> ⚠️ 密碼不要寫進任何檔案、Teams 訊息、Email，也不要貼進 Claude 的對話框。
> 交付給本人請循公司密碼保管流程。

### 看有哪些帳號、誰能封存

```powershell
node scripts/create-user.mjs --list
node scripts/grant-freeze.mjs --list
```

### 有人離職或新人接手

授予封存權限：

```powershell
node scripts/grant-freeze.mjs 新的email@makalot.com.tw
```

收回：

```powershell
node scripts/grant-freeze.mjs --revoke 舊的email@makalot.com.tw
```

> 系統會拒絕把「最後一位還能封存的人」收回，避免變成沒有人能封存。
> 所以順序是**先給新的人，再收回舊的人**。
